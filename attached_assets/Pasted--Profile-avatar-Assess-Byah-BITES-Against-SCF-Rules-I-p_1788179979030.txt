The two Soroban contracts: genuinely solid
Both msme-credential/src/lib.rs and creator-contribution/src/lib.rs are real, compilable-looking Soroban contracts, not placeholders:

msme-credential: initialize() sets a single allowlisted issuer with require_auth(); issue() re-checks require_auth() + issuer allowlist, rejects empty PSGC/circuit fields and invalid status enums, and rejects re-issuing an existing subject ("credential already exists"); get() computes an Expired status live from expires_at at read time rather than trusting stored state.

creator-contribution: record() requires the creator's own signature, rejects empty circuit IDs, and enforces write-once semantics via a (creator, content_hash) composite key ("duplicate contribution").

Both use #![no_std], proper #[contracttype] storage structs, and separate persistent vs instance storage appropriately for credential/contribution records vs. the issuer config.

Each file ships 3 embedded #[cfg(test)] unit tests covering the happy path, the duplicate/overwrite rejection, and (for msme-credential) the unauthorized-issuer rejection.

Both pin soroban-sdk = "=25.0.0" and use env.register_contract(...) in tests — this call is deprecated in favor of env.register(...) in the current SDK, but deprecated (not removed) APIs still compile with a warning, so this is a code-quality nit, not a build blocker.

This part of the repo backs up the README's core technical claims.
